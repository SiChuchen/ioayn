# 00 — Project Charter

## 项目名称

**IOAYN — Input/Output Is All You Need**

中文定位：输入输出驱动的复杂代码学习方法、持续认知记忆与 Agent 框架。

## 问题定义

大型代码库难以学习，不只是代码量大，而是学习者缺少三种能力：

1. 决定当前应该理解什么、应该停在哪个抽象层；
2. 区分哪些未知会阻塞当前理解，哪些可以以后再学；
3. 把今天形成的局部认知放回整个项目，和昨天的认知建立连接。

传统方式常见失败：

- 从 `main` 或目录树开始，遇到每个依赖都继续展开；
- 生成大量静态 Markdown，但用户不知道下一步学什么；
- 全仓库图节点过多，无法解释一个具体场景；
- 函数名和类型名被当成知识，却没有说明它们在当前路径中的角色；
- 静态推断、运行事实和未知被流畅语言混在一起；
- 会话结束后重新探索，认知不能持续积累；
- 用户知道“学过”，却不知道这部分在系统哪里、与前面有什么关系。

## 核心假设

软件实体可以先通过当前场景中的广义 I/O 契约理解：

```text
输入从哪里来
→ 谁消费
→ 发生什么转换、状态变化或副作用
→ 产生什么输出
→ 谁继续消费
```

当这一层足以回答问题时，不必理解内部全部实现；不足时，再把其中一个参与者作为新的黑盒继续执行相同方法。

## 产品使命

让 Agent 能够：

1. 把模糊学习诉求转成有限目标与 L0–L5 抽象层级；
2. 找到可观察或有语义的入口；
3. 建立小型纵向 Learning Slice；
4. 为每个新实体提供上下文角色；
5. 控制下钻深度与认知负载；
6. 用源码和运行证据验证；
7. 通过 checkpoint 让用户形成自己的模型；
8. 保存原始学习过程和可复用认知结果；
9. 将学习资产放入 Cognitive Atlas；
10. 跨会话连接、修正和恢复认知。

## 成功定义

IOAYN 的成功不以文档数量、图节点数量或 Agent 输出长度衡量，而以用户能否：

- 更快定位目标路径；
- 少打开无关文件；
- 准确复述 I/O、状态和关键参与者；
- 对变化或失败做出正确预测；
- 几天后恢复到原有认知位置；
- 看清当前知识位于项目哪里；
- 发现与历史学习的连接；
- 识别结论的证据、confidence 和 freshness；
- 明确认知链仍然断在哪里。

## 非目标

IOAYN 不是：

- 完整 API 文档生成器；
- 全仓库调用图浏览器；
- 静态分析器、调试器或 Profiler 本身；
- 自动执行任意代码的 Agent；
- 用 I/O 取代算法、架构、领域知识的还原论；
- 用完成百分比代表掌握程度的课程系统；
- 默认上传私有源码或原始对话的云知识库。

## 产品原则

- **Goal-first**：目标先于仓库结构。
- **Level-aware**：先确认学习层级。
- **Observable-first**：从可观察行为或语义锚点开始。
- **Contract-first**：实体必须说明当前场景角色。
- **Slice-first**：先纵向贯通，再横向归纳。
- **Evidence-first**：事实必须可回溯。
- **Learner-active**：用户需要预测、解释和修正。
- **Memory-separated**：原始交流与复用知识分层。
- **Atlas-bounded**：地图用于定位和连接，不展示毛线团。
- **Revision-aware**：长期认知绑定代码版本。
- **Provider-neutral**：底层工具可替换。
- **Human-controllable**：执行与隐私受用户控制。
