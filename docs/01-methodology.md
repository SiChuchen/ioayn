# 01 — IOAYN Methodology

## 方法论定义

IOAYN 是一种目标驱动、层级明确、边界优先、输入输出导向的代码学习方法。

最小认知单元不是文件、目录或类，而是能够回答一个具体问题的 **Learning Slice**：

```text
可观察输入
→ 系统或模块边界
→ 生产者
→ 转换者 / 状态持有者
→ 输出或副作用
→ 消费者
```

## 为什么不默认从 main 开始

`main` 是生命周期入口，不一定是业务或认知入口。沿代码依赖展开会形成：

```text
为了理解 A 打开 B
→ 为了理解 B 打开 C / D / E
→ 为了理解 C 再打开 F / G
→ 失去原始问题
```

IOAYN 只解决当前目标继续前进所需的阻塞问题。

## L0–L5 抽象层级

- `L0`：产品或问题场景——系统对外表现什么；
- `L1`：系统边界——主要参与者交换什么；
- `L2`：端到端路径——输入怎样形成输出；
- `L3`：模块契约——读写状态、失败和副作用；
- `L4`：组件协作——函数、线程、进程、队列怎样配合；
- `L5`：实现机制——算法、内存、并发、协议、内核细节。

默认从 L1/L2 建立意义，只有当前层无法回答问题或用户主动选择时才进入更深层。

## 上下文角色

代码实体只有放入切片才具有学习意义。同一函数在不同路径可能扮演不同角色。

最小角色表达：

```text
输入 → 做什么 → 输出或副作用
```

例如：

```text
entry()
输入：已准备的探测上下文
动作：启动并协调 sender / receiver
输出：把存活目标写入结果队列
```

函数名、结构体名或文件名本身不构成教学内容。

## 认知类型

- `FACT`：当前源码或运行证据直接支持；
- `INFERENCE`：由事实推导出的解释；
- `UNKNOWN`：当前证据不足；
- `CONFLICT`：可信证据相互矛盾。

每条重要 claim 带 `high / medium / low` confidence。表达流畅度不能提高 confidence。

## 未知分类

- `blocking`：不解决会使当前路径可能错误；
- `non_blocking`：当前知道角色即可；
- `deferred`：属于其他目标或更深层。

## 认知预算

引导式教学默认每轮：

- 5 个新实体；
- 3 个新文件；
- 3 个新技术概念；
- 8 个可视流程节点。

Agent 内部可以读取更多源码，但用户侧先看到摘要路径和子层选择。

## 标准循环

```text
定义目标与层级
→ 找入口
→ 建黑盒契约
→ 追踪生产消费链
→ 分类 claim 和 unknown
→ 必要时验证
→ 教学 checkpoint
→ 提炼 LearningAsset
→ 提交 LearningRound
→ 更新 Cognitive Atlas
→ 选择下一下钻
```

## 局部与整体

用户可以只完成一个切片。整体理解不是一次性扫描整个仓库，而是多个已验证切片的横向归纳：

```text
切片 A + 切片 B + 切片 C
→ 发现共享模块、状态、概念和边界
→ 形成系统级模型
```

## 运行证据

静态代码表示可能路径，运行 Trace 表示特定场景实际经过的路径。两者冲突时必须保留冲突并重新建模，不能静默选择更符合原假设的证据。

## 每轮结束

一轮教学只有在以下条件满足后才结束：

- 用户收到有限教学步骤；
- 新实体有角色；
- claim 与 unknown 显式；
- checkpoint 状态已记录；
- `commit_learning_round` 成功或失败被明确报告；
- Atlas delta 告诉用户这块认知放在哪里。
