## Not executed in this environment

### Claude Code CLI plugin validation

The Claude Code CLI is not installed in the build container. Therefore this release does **not** claim that `claude plugin validate` or an actual `/ioayn:learn-code` session was executed here.

The project follows the documented Claude Code plugin layout and includes the installable bundle, but the user environment should still verify:

```bash
claude --plugin-dir /path/to/ioayn-v1.1.0
```

Then inspect `/mcp`, `/agents`, `/help`, and run one persistent learning round.

### Full real-project toolchain rerun

The WVSS test validated the learning methodology but did not have MCP, Hooks, or Atlas connected. A full v1.1 field rerun remains the next P0 release-follow-up task.

## Known architectural limitations

- JSON multi-file transactions are recoverable and idempotent, but not database ACID transactions.
- Hook capture records turn-level user prompts and final assistant messages, not hidden model reasoning.
- Atlas semantic links are currently proposed by the Agent/curator; no dedicated graph UI exists.
- Freshness is source-repository-level, not symbol-level invalidation.
- No general CodeProvider or RuntimeProvider is bundled yet.

These limitations are explicit product scope, not hidden test failures.
